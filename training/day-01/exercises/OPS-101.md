# Lab OPS-101 — Filter incidents by severity

**Day 01 | 15:00–16:15 implementation lab; 16:15–16:30 review**  
**Source of truth:** `../../docs/OPS-101.md` (open from repository root as `docs/OPS-101.md`).

## Scenario

An IT operations user must be able to list incidents by severity. The existing `GET /incidents` endpoint returns every incident, even when a `severity` query parameter is supplied. The starter is intentionally incomplete.

### Acceptance criteria

1. `GET /incidents` accepts an **optional** `severity` query parameter.
2. Allowed values: `critical`, `high`, `medium`, `low` (lowercase, exact match).
3. No parameter means existing unfiltered behavior.
4. Filtering returns **only matching** incidents, sorted by `id` ascending.
5. Unsupported value (e.g., `urgent`) returns HTTP **422**, using FastAPI's standard validation response.
6. Existing endpoints and payload shapes remain unchanged.
7. All baseline and OPS-101 tests pass after implementation.

**Out of scope:** authentication, pagination, case-insensitive filtering, UI and connections to production Jira or customer systems.
